Direction A — editorial textbook, handed off to the codebase.

How to apply the Direction A v2 design to the existing Vite + TypeScript codebase without changing simulation logic. Written for an engineer taking the Figma‑equivalent (the HTML mockup) into production. Keep this doc next to the PR.

Target · photoelectric‑effect repo Stack · Vite · TS · Capacitor Scope · style.css + 15 HTML shells + landing.ts Typography · Lora + Lato (existing, kept)

§ 1Overview & non‑goals

This is a styling + layout refresh, not a rewrite. Every simulation's math, canvas, and event‑handler logic stays intact. What changes is the chrome around it: nav pattern, color tokens, type scale, spacing rhythm, and a handful of reused UI components.

In scope

  • Rewrite style.css tokens (colors, spacing, radius, shadows)
  • Restyle existing component classes (.main-nav, .glass-panel, .control-panel, sliders, cards)
  • Update each *.html shell's nav + header markup to breadcrumb + figure pattern
  • Extend landing.ts rendering: resume card, progress strip, chapter TOC
  • Add 2 new classes: .fig-caption, .readouts

Out of scope

  • Simulation math (photoelectric.ts, bohrSimulation.ts, etc.) — unchanged
  • Canvas rendering logic (graph.ts, transmissionGraph.ts) — only stroke colors via CSS vars
  • Capacitor plugins and app-init — unchanged
  • Font files — keep Lora & Lato, already self‑hosted for offline mobile

Principle

If a .ts file changes, you're doing it wrong. Everything here is CSS, HTML markup, and template rendering in landing.ts/simulations.ts. The simulation engines themselves don't know the redesign happened.

Why Lato carries mono duty

The mockup uses JetBrains Mono for readouts + eyebrows. You don't have it self‑hosted and we agreed (B) no new fonts. Lato at 600 weight + tabular‑nums + wide tracking reads as monospace‑adjacent for short labels. Reserve it for 10–14px; longer technical strings stay Lora.

TypeScript · landing.ts render functions to add

interface Chapter { num: string; title: string; weeks: string; sims: Sim[]; }
interface Sim { id: string; title: string; href: string; done: boolean; }

function renderResume(last: ResumeState) {
  const pct = Math.round((last.step / last.total) * 100);
  return `
    <div class="resume-inner">
      <div class="eyebrow">Continue reading</div>
      <div class="resume-title">§ ${last.section} · ${last.title}</div>
      <div class="resume-sub">You stopped on "${last.bookmark}".</div>
      <div class="qc-prog">
        ${Array.from({length: last.total}, (_, i) =>
          \`<div class="tick ${i < last.step ? 'done' : ''}"></div>\`
        ).join('')}
      </div>
      <div class="byline">${last.step} / ${last.total} min</div>
    </div>`;
}

function renderProgressStrip(chapters: Chapter[]) {
  return chapters.map(c => {
    const done = c.sims.filter(s => s.done).length;
    const pct = (done / c.sims.length) * 100;
    return `
      <div class="cp-seg" style="flex:${c.sims.length}">
        <div class="cp-fill" style="width:${pct}%"></div>
        <span class="cp-label">${c.num}</span>
      </div>`;
  }).join('');
}

function renderTOC(chapters: Chapter[]) {
  return chapters.map(c => {
    const done = c.sims.filter(s => s.done).length;
    return `
      <a class="toc-row" href="#ch-${c.num}">
        <span class="num">${c.num}</span>
        <div class="body">
          <div class="title">${c.title}</div>
          <div class="meta byline">${c.weeks} · ${done}/${c.sims.length} done</div>
          <div class="qc-prog micro meta">
            ${c.sims.map(s =>
              \`<div class="tick ${s.done ? 'done' : ''}"></div\>\`
            ).join('')}
          </div>
        </div>
        <span class="chev">›</span>
      </a>`;
  }).join('');
}

Archetype rules

  • Diagram + graph: framed diagram first, readouts, controls, then secondary graph with its own fig‑caption. (Photoelectric, Bohr, Particle 1D, Barrier)
  • 3D scene: dark canvas is hero. Controls collapse to chip grids for quantum numbers, two sliders max. (Orbitals, Hybridization, Particle 2D)
  • Graph‑dominant: graph is the figure itself. Molecule/parameter chips above, band/characteristic table below. (IR, Rot, VibRot, Blackbody, Basis)

§ 9Gotchas

  • Canvas stroke colors: any .ts file that hardcodes stroke colors (e.g. graph.ts) needs two changes — default stroke becomes getComputedStyle(document.documentElement).getPropertyValue('--accent'), and axis/grid lines use --line or rgba(255,255,255,.15) for dark viewports.
  • KaTeX: the existing @import "katex/dist/katex.min.css" at the top of style.css stays; override .katex color to var(--ink).
  • Italic accent word: the Lora italic variant is weight 400 only. If you want italic at 500, the redesign uses upright 500 accent‑coloured instead — do not fake italic.
  • Mobile gutters: always var(--s-5) (20px). The one exception is the sim canvas wrapper, which extends to gutters but its <canvas> keeps its internal margin.
  • Capacitor: no network font calls. The design uses only Lora + Lato, already bundled in public/fonts/. Do not introduce Fraunces / Newsreader / JetBrains Mono.
  • Status bar: iOS status bar needs safe-area-inset-top padding on .main-nav. Already present in your style.css — keep it.

§ 10What to push back on

If any of these look wrong during implementation, stop and flag — they're design calls, not bugs.

Flat cards. The redesign removes shadows and rounded corners from panels. If a stakeholder says "it looks unfinished," the answer is that's the editorial‑textbook brief. The interaction affordance comes from the 1px line, not depth.
No hover states on touch. Chips and TOC rows use :active (invert colors) only. Do not add :hover shadows for desktop parity.
Italic accent word. Every screen title has one italic word in --accent-2. This is the single display flourish — don't italicize more words or the rhythm breaks.
